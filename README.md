# FIFA World Cup 2026 – High-Performer Classification (ML Assignment 2)

## a. Problem statement
Predict whether a player had a **high-performance match** at the FIFA World Cup 2026 from the
player's match statistics (attacking, passing, defensive, disciplinary, goalkeeping and physical
data). This is a **binary classification** problem:

* `high_performer = 1` if the match `player_rating` ≥ **5.50**
  (the dataset median), otherwise `0`.

Five classifiers (Logistic Regression, Decision Tree, KNN, Naive Bayes, SVM) are trained on the same
data and compared on Accuracy, AUC, Precision, Recall, F1 and MCC. They are deployed in an interactive
Streamlit web app.

## b. Dataset description
* **Source:** Kaggle – [FIFA World Cup 2026 Player Performance Dataset](https://www.kaggle.com/datasets/rauffauzanrambe/fifa-world-cup-2026-player-performance-dataset)
  (file `fifa_world_cup_2026_player_performance.csv`; synthetically generated by the dataset author).
* **Size:** 54,600 instances (one row per player per match) × 75 columns.
  This meets the minimum of 12 features and 500 instances.
* **Feature groups:** player profile (age, height, weight, position, preferred foot, market value),
  match context (stage, result, team/opponent goals), attacking (goals, assists, shots, xG, xA, key
  passes, dribbles), passing (passes, pass accuracy, crosses), defending (tackles, interceptions,
  clearances, blocks, aerial duels, recoveries), discipline (fouls, cards, offsides), goalkeeping
  (saves, save %, clean sheet, goals conceded) and physical (distance, sprint distance, top speed,
  accelerations, stamina).
* **Target:** `high_performer`. Class balance: 1 = 50.59%, 0 = 49.41%.
* **Features used (49):** age, height_cm, weight_kg, market_value_eur, goals_team, goals_opponent, minutes_played, goals, assists, shots, shots_on_target, expected_goals_xg, expected_assists_xa, key_passes, successful_passes, total_passes, pass_accuracy, dribbles_attempted, successful_dribbles, crosses, successful_crosses, tackles, interceptions, clearances, blocks, aerial_duels_won, aerial_duels_lost, recoveries, defensive_actions, fouls_committed, fouls_suffered, yellow_cards, red_cards, offsides, saves, save_percentage, punches, clean_sheet, goals_conceded, penalty_saves, distance_covered_km, sprint_distance_km, accelerations, decelerations, stamina_score, position, preferred_foot, tournament_stage, match_result.
* **Columns removed:** *target_source / leakage*: player_rating, performance_score, offensive_contribution, defensive_contribution, possession_impact, pressure_resistance, creativity_score, consistency_score, clutch_performance_score, total_goals_tournament, total_assists_tournament, total_minutes_tournament, player_of_match_awards, tournament_rating; *identifier*: player_id, player_name, jersey_number, club_name, match_id, match_date; *high_cardinality_text*: nationality, team, stadium, city, opponent_team; *high_corr_with_rating*: top_speed_kmh.
  These columns were removed because they are the rating itself, rating-derived composite scores,
  whole-tournament aggregates or Player-of-the-Match awards (all would leak the target), or because
  they are identifiers or high-cardinality names, or because their absolute correlation with the
  rating was ≥ 0.90 (automatic leakage check).
* **Pre-processing:** median/mode imputation, StandardScaler for numeric features, One-Hot encoding for
  categorical features. The preprocessing is fitted on the training split only and stored inside each saved pipeline.
* **Split:** stratified 80/20 train/test (random_state = 42) → 43,680 train /
  10,920 test rows. The test split is provided as `test_data.csv`.

## d. Models used
Hyper-parameters were tuned with 5-fold stratified GridSearchCV (F1 score) on the training set.
SVM uses an RBF kernel with C = 1 and gamma = 'scale'.

### Comparison Table (evaluation metrics on the hold-out test set)

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.8848 | 0.9436 | 0.8873 | 0.8847 | 0.8860 | 0.7696 |
| Decision Tree | 0.9302 | 0.9559 | 0.8788 | 1.0000 | 0.9355 | 0.8687 |
| KNN | 0.9005 | 0.9368 | 0.8803 | 0.9296 | 0.9043 | 0.8020 |
| Naive Bayes | 0.8361 | 0.9323 | 0.8795 | 0.7833 | 0.8286 | 0.6767 |
| Support Vector Machine | 0.9301 | 0.9415 | 0.8788 | 0.9998 | 0.9354 | 0.8685 |

### Observations on the performance of each model

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Logistic Regression gave steady results with 88.5% accuracy and an MCC of 0.7696. Its precision (0.887) and recall (0.885) are almost the same, so it makes both kinds of mistakes equally. Train and test accuracy are very close (0.8824 vs 0.8848), so it is not overfitting. It came 4th, which suggests a straight-line boundary cannot fully separate high and low performers. |
| Decision Tree | The Decision Tree gave the best result with 93.0% accuracy, the highest AUC (0.9559) and the highest MCC (0.8687), even with a depth of only 4. Its recall is 1.0, so it found every high performer. All of its mistakes were low performers wrongly marked as high. Train and test accuracy are almost equal, so it is not overfitting. A few simple rules are enough to separate the two classes in this dataset. |
| KNN | KNN came 3rd with 90.1% accuracy and an MCC of 0.8020, using 11 neighbours. Its recall (0.930) is higher than its precision (0.880), so it catches most high performers but also wrongly flags some low performers. Train and test accuracy are close (0.9036 vs 0.9005), so it generalises well. It did better than Logistic Regression but stayed behind the Decision Tree and SVM. |
| Naive Bayes | Naive Bayes was the weakest model with 83.6% accuracy and an MCC of 0.6767. It had the lowest recall (0.783), so it missed more high performers than any other model. Train and test accuracy are nearly the same, so the problem is not overfitting; the model is too simple for this data. It treats every feature as independent, but related statistics such as shots, shots on target and xG move together. |
| Support Vector Machine | The SVM came 2nd with 93.0% accuracy and an MCC of 0.8685, almost tied with the Decision Tree. It has the same precision (0.8788) and nearly the same recall (0.9998), so it learned almost the same separation as the tree. Train and test accuracy are close, so there is no overfitting. Its AUC (0.9415) is lower than the Decision Tree's, so its scores rank players a little less well. It was trained on 20,000 rows to keep training time reasonable. |
| Overall, Winner for your dataset? | **Decision Tree** is the winner. It has the best accuracy, F1, AUC and MCC. The SVM is almost equal, but the Decision Tree is simpler, faster and easier to explain, so it is the better choice for this dataset. |

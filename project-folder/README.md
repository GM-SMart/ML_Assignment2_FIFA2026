# FIFA World Cup 2026 – High-Performer Classification (ML Assignment 2)

## a. Problem statement
Predict whether a player had a **high-performance match** at the FIFA World Cup 2026 from the
player's match statistics (attacking, passing, defensive, disciplinary, goalkeeping and physical
data). This is a **binary classification** problem:

* `high_performer = 1` if the match `player_rating` ≥ **5.50**
  (the dataset median), otherwise `0`.

Five classifiers (Logistic Regression, Decision Tree, KNN, Naive Bayes, SVM) are trained on the same
data and compared on Accuracy, AUC, Precision, Recall, F1 and MCC. They are deployed in an interactive
Streamlit web app.

## b. Dataset description
* **Source:** Kaggle – [FIFA World Cup 2026 Player Performance Dataset](https://www.kaggle.com/datasets/rauffauzanrambe/fifa-world-cup-2026-player-performance-dataset)
  (file `fifa_world_cup_2026_player_performance.csv`; synthetically generated by the dataset author).
* **Size:** 54,600 instances (one row per player per match) × 75 columns.
  This meets the minimum of 12 features and 500 instances.
* **Feature groups:** player profile (age, height, weight, position, preferred foot, market value),
  match context (stage, result, team/opponent goals), attacking (goals, assists, shots, xG, xA, key
  passes, dribbles), passing (passes, pass accuracy, crosses), defending (tackles, interceptions,
  clearances, blocks, aerial duels, recoveries), discipline (fouls, cards, offsides), goalkeeping
  (saves, save %, clean sheet, goals conceded) and physical (distance, sprint distance, top speed,
  accelerations, stamina).
* **Target:** `high_performer`. Class balance: 1 = 50.59%, 0 = 49.41%.
* **Features used (56):** age, jersey_number, height_cm, weight_kg, market_value_eur, goals_team, goals_opponent, minutes_played, goals, assists, shots, shots_on_target, expected_goals_xg, expected_assists_xa, key_passes, successful_passes, total_passes, pass_accuracy, dribbles_attempted, successful_dribbles, crosses, successful_crosses, tackles, interceptions, clearances, blocks, aerial_duels_won, aerial_duels_lost, recoveries, defensive_actions, fouls_committed, fouls_suffered, yellow_cards, red_cards, offsides, saves, save_percentage, punches, clean_sheet, goals_conceded, penalty_saves, distance_covered_km, sprint_distance_km, accelerations, decelerations, stamina_score, player_of_match_awards, nationality, team, position, preferred_foot, stadium, city, opponent_team, tournament_stage, match_result.
* **Columns removed:** *target_source / leakage*: player_rating, performance_score, offensive_contribution, defensive_contribution, possession_impact, pressure_resistance, creativity_score, consistency_score, clutch_performance_score, total_goals_tournament, total_assists_tournament, total_minutes_tournament, tournament_rating; *identifier*: player_id, player_name, club_name, match_id, match_date; *high_corr_with_rating*: top_speed_kmh.
  These columns were removed because they are the rating itself, rating-derived composite scores,
  whole-tournament aggregates or the Player-of-the-Match flag (all would leak the target), or because
  they are identifiers or high-cardinality names.
* **Pre-processing:** median/mode imputation, StandardScaler for numeric features, One-Hot encoding for
  categorical features. The preprocessing is fitted on the training split only and stored inside each saved pipeline.
* **Split:** stratified 80/20 train/test (random_state = 42) → 43,680 train /
  10,920 test rows. The test split is provided as `test_data.csv`.

## d. Models used
Hyper-parameters were tuned with 5-fold stratified GridSearchCV (F1 score) on the training set.
SVM uses an RBF kernel with C = 1 and gamma = 'scale'.

### Comparison Table (evaluation metrics on the hold-out test set)

| ML Model Name | Accuracy | AUC | Precision | Recall | F1 | MCC |
|---|---|---|---|---|---|---|
| Logistic Regression | 0.8817 | 0.9432 | 0.8856 | 0.8798 | 0.8827 | 0.7634 |
| Decision Tree | 0.9302 | 0.9559 | 0.8788 | 1.0000 | 0.9355 | 0.8687 |
| KNN | 0.8853 | 0.9381 | 0.8799 | 0.8955 | 0.8877 | 0.7707 |
| Naive Bayes | 0.8344 | 0.9313 | 0.8806 | 0.7782 | 0.8263 | 0.6739 |
| Support Vector Machine | 0.9301 | 0.9411 | 0.8788 | 0.9998 | 0.9354 | 0.8685 |

### Observations on the performance of each model

| ML Model Name | Observation about model performance |
|---|---|
| Logistic Regression | Rank 4/5 by MCC (train acc 0.8834 vs test acc 0.8817, gap +0.0017). Train and test scores are close, so it generalises well (no overfitting). It is beaten by the non-linear models, which means interactions between the statistics (for example, position combined with defensive actions) matter. A single linear boundary misses these. Precision (0.886) and recall (0.880) are balanced. |
| Decision Tree | Rank 1/5 by MCC (train acc 0.9273 vs test acc 0.9302, gap -0.0029). Train and test scores are close, so it generalises well (no overfitting). The tuned tree (max_depth=4, min_samples_leaf=1) is pruned to limit variance. Axis-aligned threshold splits capture non-linear rules (for example, goals ≥ 1 together with a high pass accuracy), so it beats the linear baseline. |
| KNN | Rank 3/5 by MCC (train acc 0.8875 vs test acc 0.8853, gap +0.0021). Train and test scores are close, so it generalises well (no overfitting). KNN (n_neighbors=21) relies on distances in a 56-feature scaled space. It is competitive here, so performance profiles form clear local neighbourhoods. It is also the slowest model at prediction time because it stores the entire training set. |
| Naive Bayes | Rank 5/5 by MCC (train acc 0.8340 vs test acc 0.8344, gap -0.0004). Train and test scores are close, so it generalises well (no overfitting). Gaussian NB assumes the features are independent and normally distributed. Football statistics break both assumptions: shots, shots on target and xG are strongly correlated, and counts such as goals are skewed and non-Gaussian. This makes it the weakest model, and its over-confident probabilities favour precision (P=0.881, R=0.778). On the plus side, it is the fastest model to train. |
| Support Vector Machine | Rank 2/5 by MCC (train acc 0.9273 vs test acc 0.9301, gap -0.0028). Train and test scores are close, so it generalises well (no overfitting). The RBF kernel learns a smooth non-linear margin on the standardised features (trained on a stratified 20,000-row subsample because kernel SVM training scales as O(n²)). Its AUC is below the best model, so the kernel margin offers no advantage on this data. |
| Overall, Winner for your dataset? | **Decision Tree** wins with the highest MCC (0.8687), F1 0.9355, accuracy 0.9302 and AUC 0.9559. The runner-up is Support Vector Machine (MCC 0.8685). MCC is used as the deciding metric because it accounts for all four confusion-matrix cells, so it is the most reliable single score for a binary classifier. |
